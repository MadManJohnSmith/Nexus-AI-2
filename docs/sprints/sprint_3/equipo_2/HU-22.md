## 1. Descripción de la Historia
**Como** asesor o estudiante de posgrado,  
**quiero** registrar evidencias científicas mediante enlaces persistentes DOI o URLs externas validadas por formato,  
**para** respaldar publicaciones, preprints, repositorios de código o datasets de investigación sin duplicar almacenamiento redundante.

---

## 2. Criterios de Aceptación y Validación (Gherkin)

### CA-22.1: Validación Exitosa de Identificador DOI (Estándar / URL)
```gherkin
Escenario: Registro de enlace persistente DOI
  Dado que el usuario introduce un DOI en formato estándar ('10.1016/j.jneumeth.2020.108920') o resolver ('https://doi.org/10...')
  Cuando envía la solicitud POST a '/api/v2/evidence/'
  Entonces el sistema valida la expresión regular de DOI
  Y almacena la evidencia con tipo 'ENLACE_DOI' y mime_type 'text/uri-list'
  Y responde con HTTP 201 Created.
```

### CA-22.2: Validación Exitosa de URL Externa General
```gherkin
Escenario: Registro de repositorio GitHub o dataset externo
  Dado que el usuario introduce una URL HTTP/HTTPS válida
  Cuando envía la solicitud
  Entonces el sistema la acepta y almacena como enlace externo.
```

### CA-22.3: Rechazo de Formato Inválido
```gherkin
Escenario: Rechazo de texto no compatible con DOI ni URL
  Dado que el usuario envía una cadena de texto sin protocolo ni estructura DOI válida
  Cuando se valida el payload
  Entonces el backend responde con HTTP 400 Bad Request y mensaje de error en 'enlace_url'.
```

---

## 3. Arquitectura e Implementación Técnica
- Expresión Regular de Validación DOI/URL:
  `r'^(10\.\d{4,9}/[-._;()/:A-Za-z0-9]+|https?://(dx\.)?doi\.org/10\.\d{4,9}/[-._;()/:A-Za-z0-9]+|https?://[^\s/$.?#].[^\s]*)$'`
- Serializador `EvidenceCreateSerializer` y validador de modelo `Evidence.clean()`.
