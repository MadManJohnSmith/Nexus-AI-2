## 1. Descripción de la Historia
**Como** asesor, coordinador o estudiante responsable,  
**quiero** cambiar el estado del acuerdo (Pendiente, En Proceso, Concluido, Vencido) adjuntando comentarios y notas de justificación,  
**para** mantener una bitácora inmutable de auditoría y trazar con precisión la evolución del compromiso.

---

## 2. Criterios de Aceptación y Validación (Gherkin)

### CA-13.1: Transición a Estado Concluido y Fecha de Conclusión
```gherkin
Escenario: Conclusión de acuerdo
  Dado un acuerdo en estado 'PENDIENTE' o 'EN_PROCESO'
  Cuando el usuario autorizado envía POST a '/api/v2/agreements/{id}/update-status/' con estado='CONCLUIDO' y un comentario de resolución
  Entonces el sistema responde con HTTP 200 OK
  Y el estado del acuerdo pasa a 'CONCLUIDO'
  Y se asigna automáticamente la fecha_conclusion al día actual.
```

### CA-13.2: Registro Inmutable en AgreementAuditLog
```gherkin
Escenario: Registro de bitácora de cambio de estado
  Dado que se realiza cualquier cambio de estado en un acuerdo
  Cuando la transacción finaliza exitosamente
  Entonces se inserta un registro en 'AgreementAuditLog' conteniendo:
    | user           | ID del usuario autenticado |
    | estado_anterior| Estado previo              |
    | estado_nuevo   | Nuevo estado asignado      |
    | comentario     | Nota de justificación      |
    | fecha_cambio   | Marca de tiempo exacta     |
```

### CA-13.3: Consulta de Historial de Auditoría
```gherkin
Escenario: Consulta del historial de transiciones de un acuerdo
  Dado un acuerdo con múltiples transiciones previas
  Cuando se envía una petición GET a '/api/v2/agreements/{id}/audit-logs/'
  Entonces el sistema retorna la lista cronológica descendente de cambios de estado con HTTP 200 OK.
```

## 3. Arquitectura e Implementación Técnica

### 3.1 Modelo de Auditoría (`backend/apps/agreements/models.py`)
- Modelo `AgreementAuditLog`:
  - `agreement`: `ForeignKey` a `Agreement` (`on_delete=models.CASCADE`, `related_name='audit_logs'`).
  - `user`: `ForeignKey` a `CustomUser` (`null=True`, `on_delete=models.SET_NULL`).
  - `estado_anterior`: `CharField(max_length=20)`.
  - `estado_nuevo`: `CharField(max_length=20)`.
  - `comentario`: `TextField(blank=True, default='')`.
  - `fecha_cambio`: `DateTimeField(auto_now_add=True)`.

### 3.2 Acción DRF (`backend/apps/agreements/views.py`)
- `@action(detail=True, methods=['post'], url_path='update-status')`: Realiza la transición atómica y genera el log de auditoría.
- `@action(detail=True, methods=['get'], url_path='audit-logs')`: Retorna la lista de auditorías del acuerdo.

### 3.3 Componente Angular (`AgreementDrawerComponent`)
- Modo `STATUS_UPDATE`: Permite seleccionar el nuevo estado mediante cards interactivas (#57949D, #B57136, #437E5C, #A14D98).
- Área de texto para notas de resolución.
- Visualización de la línea temporal (Timeline) de cambios históricos con usuario, fecha y notas.
