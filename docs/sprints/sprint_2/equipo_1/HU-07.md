# Historia de Usuario HU-07: Registrar Sesión de Tutoría

**Sprint:** 2  
**Épica:** E02 — Gestión y Seguimiento de Tutorías  
**Equipo Responsable:** Equipo 1 (Núcleo y Tutorías — Devs 1 a 5)  
**Story Points:** 5 SP  
**Prioridad:** Crítica (Must)  
**Estado:** Done  

---

## 1. Descripción de la Historia
**Como** asesor doctoral o coasesor,  
**quiero** registrar una sesión de tutoría con fecha, semestre, modalidad y resumen,  
**para** conservar evidencia digital formal del seguimiento académico brindado al estudiante.

---

## 2. Criterios de Aceptación y Validación (Gherkin)

```gherkin
Escenario: Registro exitoso de sesión de tutoría
  Dado que un asesor autenticado está asignado al comité del estudiante con ID 1
  Y el estudiante tiene registrado el Semestre 1
  Cuando envía una petición POST a /api/v2/tutoring-sessions/ con fecha, modalidad y resumen
  Entonces el sistema responde con HTTP 201 Created
  Y retorna el identificador tutoring_session_created_id con el objeto creado.

Escenario: Validación de campos obligatorios
  Dado que faltan datos obligatorios (estudiante, semestre o fecha de sesión)
  Cuando se envía la petición de registro
  Entonces el sistema responde con HTTP 400 Bad Request indicando los errores de campo.
```
