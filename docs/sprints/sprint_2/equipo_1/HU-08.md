# Historia de Usuario HU-08: Registrar Modalidad y Participantes en Sesión de Tutoría

**Sprint:** 2

**Equipo Responsable:** Equipo 1 (Devs 1 a 5)

**Prioridad:** Crítica (Must Have)  
**Estado:** Done (100% Tests Passing)

---

## 1. Descripción de la Historia
**Como** asesor principal, coasesor o coordinador académico,  
**quiero** registrar una sesión de tutoría doctoral especificando su modalidad (Presencial, Virtual o Híbrida) y la lista de participantes convocados con su respectivo rol y estatus de asistencia,  
**para** mantener un registro fidedigno y auditable de las reuniones de acompañamiento tutorial y del quórum académico de cada sesión.

---

## 2. Criterios de Aceptación y Validación (Gherkin)

### CA-08.1: Registro de modalidad válida y participantes con roles
```gherkin
Escenario: Registro exitoso de sesión presencial con comité tutorial
  Dado que un asesor autenticado registra una tutoría para su tutorado
  Cuando envía un POST a '/api/v2/tutoring-sessions/' con:
    | student               | ID del estudiante             |
    | semester              | ID del semestre correspondiente|
    | fecha_sesion          | 2024-03-15                   |
    | modalidad             | PRESENCIAL                   |
    | resumen               | Revisión de metodología      |
    | participants          | Lista de usuarios y roles    |
  Entonces el sistema responde con HTTP 201 Created
  Y el cuerpo incluye "tutoring_session_created_id", mensaje de confirmación y el objeto enriquecido con nombres y roles calculados.
```

### CA-08.2: Control de asistencia individual por participante
```gherkin
Escenario: Registro de asistencia booleana y notas por participante
  Dado que se convoca a estudiante, asesor y coasesor a la sesión
  Cuando se envía el array de participantes con asistencia=true o asistencia=false y notas opcionales
  Entonces se almacena en la tabla TutoringParticipant cada registro asociado de forma atómica.
```

### CA-08.3: Validación de modalidad permitida
```gherkin
Escenario: Rechazo de modalidad inválida
  Dado que se envía un valor de modalidad fuera de ['PRESENCIAL', 'VIRTUAL', 'HIBRIDA']
  Cuando se procesa la solicitud
  Entonces el backend responde con HTTP 400 Bad Request indicando que la modalidad es inválida.
```

## 3. Arquitectura e Implementación Técnica

### 3.1 Modelos de Datos (`backend/apps/tutoring/models.py`)
- `TutoringSession`:
  - `student`: `ForeignKey` a `apps.students.models.Student` (CASCADE, `related_name='tutoring_sessions'`).
  - `semester`: `ForeignKey` a `apps.students.models.Semester` (CASCADE, `related_name='tutoring_sessions'`).
  - `fecha_sesion`: `DateField(db_index=True)`.
  - `modalidad`: `CharField(max_length=20, choices=[('PRESENCIAL', 'Presencial'), ('VIRTUAL', 'Virtual'), ('HIBRIDA', 'Híbrida')], default='PRESENCIAL')`.
  - `resumen`: `TextField()`.
  - `created_by`: `ForeignKey` a `settings.AUTH_USER_MODEL` (`null=True, blank=True, on_delete=models.SET_NULL`).
  - `created_at`, `updated_at`.
- `TutoringParticipant`:
  - `session`: `ForeignKey` a `TutoringSession` (CASCADE, `related_name='participants'`).
  - `user`: `ForeignKey` a `settings.AUTH_USER_MODEL` (CASCADE, `related_name='tutoring_attendances'`).
  - `rol_en_sesion`: `CharField(max_length=30, choices=[('ESTUDIANTE', 'Estudiante'), ('ASESOR_PRINCIPAL', 'Asesor Principal'), ('COASESOR', 'Coasesor'), ('VOCAL', 'Vocal'), ('SECRETARIO', 'Secretario'), ('INVITADO', 'Invitado')])`.
  - `asistencia`: `BooleanField(default=True)`.
  - `notas`: `CharField(max_length=255, blank=True, default='')`.
  - Constraint: `UniqueConstraint(fields=['session', 'user'], name='unique_session_participant')`.

### 3.2 Serializadores y Endpoints REST v2.0 (`backend/apps/tutoring/`)
- `TutoringSessionCreateSerializer`: maneja la creación atómica anidada de sesión y participantes.
- `TutoringSessionSerializer`: serializador de lectura enriquecida con `student_nombre`, `semester_numero`, `modalidad_display`, `participants` y `total_participantes`.
- Endpoint: `POST /api/v2/tutoring-sessions/` y `GET /api/v2/tutoring-sessions/`.

### 3.3 Frontend Angular 20 Standalone (`frontend/src/app/features/tutoring/tutoring-modal/`)
- `tutoring-modal.component.ts` & `.html`:
  - Selector de modalidad con opciones estándar (Presencial, Virtual, Híbrida).
  - Lista de participantes con checkbox de asistencia reactivo y badge de rol.
  - Sincronización con `TutoringService.createSession()`.
