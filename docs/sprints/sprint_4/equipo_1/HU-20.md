**Sprint:** 4  
**Épica:** E04 — Tesis, Producción Científica y Evidencias  
**Equipo Responsable:** Equipo 1 (Dev 5)  
**Story Points:** 3 SP  
**Prioridad:** Media (Should)  
**Estado:** Done  

---

## 1. Descripción de la Historia
**Como** estudiante de posgrado o investigador asesor,  
**quiero** registrar productos de desarrollo tecnológico, patentes, propiedad intelectual, software y bases de datos con evidencias asociadas, y gestionar toda la producción académica desde una interfaz interactiva con sub-pestañas especializadas,  
**para** consolidar integralmente la transferencia tecnológica y producción científica en el expediente doctoral.

---

## 2. Criterios de Aceptación y Validación (Gherkin)

### CA-20.1: Registro de Producto Tecnológico / Patente / Software
```gherkin
Escenario: Registro exitoso de desarrollo de software con evidencia
  Dado que un asesor o estudiante autenticado envía una petición POST a '/api/v2/academic-output/other-products/' con:
    | student | tipo_producto | titulo | descripcion | fecha_registro |
    | 1       | "SOFTWARE"    | "BioVision ML Suite v1.0" | "Librería de segmentación celular" | "2025-05-10" |
  Entonces el sistema valida y almacena el registro
  Y responde con HTTP 201 Created
  Y el cuerpo contiene "other_product_created_id", "mensaje": "Producto académico registrado correctamente" y los datos serializados.
```

### CA-20.2: Interfaz Frontend con Pestañas Especializadas y Modales Reactivos
```gherkin
Escenario: Visualización y alta en el módulo de Producción Académica
  Dado que el usuario navega a '/academic-output'
  Entonces visualiza 4 sub-pestañas: "Publicaciones", "Congresos", "Estancias Doctorales" y "Otros Productos"
  Y puede abrir formularios reactivos para registrar nuevos productos vinculando evidencias documentales o identificadores DOI.
```

### CA-20.3: Control de Acceso y Aislamiento por Roles
```gherkin
Escenario: Filtrado de otros productos académicos por comités asignados
  Dado que un asesor autenticado consulta '/api/v2/academic-output/other-products/'
  Entonces solo recibe los productos de sus estudiantes asignados.
```

## 3. Arquitectura e Implementación Técnica

### 3.1 Modelo de Datos (`backend/apps/academic_output/models.py`)
- `OtherProduct`:
  - `student`: ForeignKey `Student` (`on_delete=CASCADE`, `related_name='other_products'`).
  - `tipo_producto`: `CharField(max_length=30)` choices (`SOFTWARE`, `PROTOTIPO`, `PATENTE`, `BASE_DATOS`, `OTRO`).
  - `titulo`: `CharField(max_length=255)`.
  - `descripcion`: `TextField()`.
  - `fecha_registro`: `DateField` indexado (`default=timezone.now`).
  - `evidencia`: ForeignKey `apps.evidence.models.Evidence` (`on_delete=SET_NULL`, `null=True`, `blank=True`).
  - `created_at`, `updated_at`.

### 3.2 Endpoints y Serializadores (`serializers.py`, `views.py`)
- `OtherProductSerializer` y `OtherProductCreateSerializer`.
- `OtherProductViewSet` con filtros por estudiante y tipo de producto.

### 3.3 Frontend Angular 20 Standalone (`frontend/src/app/`)
- Modelo: `core/models/academic-output.model.ts`.
- Servicio: `core/services/academic-output.service.ts` con integración a los 4 endpoints REST v2.0.
- Componente: `features/academic-output/academic-output.component.*` con control flow nativo (`@if`, `@for`), Signals de estado reactivo, semáforos de tipo/estado y modales de alta con validación.
