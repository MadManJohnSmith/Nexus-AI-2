# Historia de Usuario HU-16: Comparativa Histórica y Evolución Longitudinal de Tesis

**Sprint:** 4  
**Épica:** E04 — Tesis, Producción Científica y Evidencias  
**Equipo Responsable:** Equipo 2 (Devs 6 a 10)  
**Story Points:** 8 SP  
**Prioridad:** Alta (Must)  
**Estado:** Done  

---

## 1. Descripción de la Historia
**Como** miembro del comité tutorial (asesor principal, coasesor, sínodos) o coordinador del programa doctoral,  
**quiero** visualizar la evolución y comparativa histórica longitudinal del avance de tesis del doctorando a lo largo de los semestres 1 al 6 con el desglose de sus componentes y porcentajes acumulados,  
**para** evaluar el progreso continuo del proyecto de investigación, identificar oportunamente estancamientos metodológicos y verificar el cumplimiento de los hitos terminales sin sobreescribir los registros pasados.

---

## 2. Criterios de Aceptación y Validación (Gherkin)

### CA-16.1: Endpoint de Historial Longitudinal de Tesis
```gherkin
Escenario: Consulta exitosa de la evolución histórica de un estudiante
  Dado que un usuario autenticado y autorizado (Coordinador, Asesor asignado o el Estudiante titular)
  Cuando realiza una petición GET a '/api/v2/thesis/history/?student_id={id}' (o '?student={id}')
  Entonces el sistema responde con HTTP 200 OK
  Y el payload JSON contiene:
    | campo             | tipo     | descripción                                           |
    | student_id        | number   | ID del doctorando                                     |
    | total_registros   | number   | Conteo total de registros históricos                  |
    | progreso_actual   | number   | Porcentaje del registro más reciente (0-100)          |
    | historico         | array    | Lista ordenada cronológicamente de semestres 1 a 6    |
  Y cada elemento del array "historico" incluye semester_numero, porcentaje_avance, fecha_registro, componentes y observaciones.
```

### CA-16.2: Preservación de Registros Históricos (No Sobreescritura)
```gherkin
Escenario: Registro de avances sucesivos en semestres posteriores
  Dado que un estudiante cuenta con avances registrados en el Semestre 1 (20%)
  Cuando el asesor registra un nuevo avance para el Semestre 2 (45%)
  Entonces el sistema crea un nuevo registro independiente en la tabla 'ThesisProgress'
  Y el historial refleja ambos hitos cronológicamente sin alterar ni sobreescribir el registro del Semestre 1.
```

### CA-16.3: Aislamiento por Roles y Permisos (RBAC)
```gherkin
Escenario: Acceso restringido por rol
  Dado un estudiante autenticado que intenta consultar el historial de otro estudiante
  Cuando envía la petición con '?student_id={otro_id}'
  Entonces el sistema deniega el acceso respondiendo con HTTP 403 Forbidden.
  
  Dado un asesor no asignado al comité tutorial del estudiante
  Cuando solicita el historial del estudiante
  Entonces el sistema responde con HTTP 403 Forbidden.
```

### CA-16.4: Integridad Relacional con Evidencias Documentales (Dev 10)
```gherkin
Escenario: Vinculación referencial entre avances de tesis y evidencias
  Dado un registro de avance de tesis con ID 'X'
  Cuando se vincula una evidencia con actividad_tipo='TESIS' y actividad_id='X'
  Entonces la evidencia mantiene integridad referencial con el estudiante y el hito de tesis.
```

## 3. Arquitectura e Implementación Técnica

### 3.1 Backend Django REST Framework (`backend/apps/thesis/`)
- **Acción ViewSet (`views.py`)**:
  - `@action(detail=False, methods=['get'], url_path='history')` en `ThesisProgressViewSet`.
  - Ordenación longitudinal por `semester__numero`, `fecha_registro` y `created_at`.
  - Soporte para parámetros `student_id` y `student`.
  - Resolución inteligente de contexto para el rol `ESTUDIANTE` (autoconsulta segura).
  - Cálculo dinámico de `progreso_actual` y estructura enriquecida de componentes.

### 3.2 Frontend Angular 20 Standalone (`frontend/src/app/features/thesis/thesis-history-chart/`)
- **Componente `ThesisHistoryChartComponent`**:
  - Standalone Component reactivo con Signals (`computed`, `signal`) y nuevo Control Flow (`@if`, `@for`).
  - Visualización gráfica de evolución semestral para los 6 semestres del doctorado:
    - Tarjetas de semestre interactivas con barras de avance vertical y semaforización de badges (CONCLUIDO, EN_PROCESO, PENDIENTE).
    - Panel detallado de componentes al seleccionar cualquier semestre (Protocolo, Estado del Arte, Marco Teórico, Metodología, Análisis, Redacción).
    - Notas cualitativas y observaciones registradas en cada periodo.
  - Integración en `StudentOverviewComponent` dentro del layout 70/30 y comunicación reactiva con `ThesisProgressFormComponent`.
