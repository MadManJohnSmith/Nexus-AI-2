## 2. Descripción de la Historia
**Como** Coordinador del Posgrado,  
**quiero** estructurar y gestionar los semestres de un estudiante (rango estricto de 1 a 6),  
**para** organizar longitudinalmente los periodos académicos donde se desarrollarán tutorías, avances de tesis y evidencias.

---

## 3. Criterios de Aceptación (Gherkin)

### CA-05.1: Rango válido de semestres (1 a 6)
- **Dado** un estudiante existente en la base de datos,
- **Cuando** se asocia un nuevo semestre con número $N \in [1, 6]$, fecha de inicio y fecha de fin válidas,
- **Entonces** el sistema persiste el registro y responde con HTTP `201 Created`.
- **Si** el valor de número de semestre es menor a 1 o mayor a 6,
- **Entonces** el sistema rechaza la solicitud con HTTP `400 Bad Request`.

### CA-05.2: Unicidad del semestre por estudiante
- **Dado** un estudiante que ya tiene registrado el Semestre 1,
- **Cuando** se intenta registrar nuevamente el Semestre 1 para dicho estudiante,
- **Entonces** la base de datos y la capa de serializadores rechazan la inserción por violación de la restricción `UniqueConstraint(student, numero)`.

### CA-05.3: Coherencia temporal de fechas
- **Dado** un registro de semestre,
- **Cuando** la `fecha_fin` es anterior a la `fecha_inicio`,
- **Entonces** la validación del modelo (`clean()`) y el serializador rechazan la solicitud con error `400 Bad Request` señalando la incongruencia de fechas.

## 4. Contrato de API REST v2.0

### Endpoint: Registro de Semestre Asociado a Estudiante
- **URL:** `/api/v2/students/<id>/semesters/`
- **Método:** `POST`
- **Cabeceras:** `Authorization: Bearer <access_token>`
- **Request Body:**
  ```json
  {
    "numero": 1,
    "fecha_inicio": "2024-01-15",
    "fecha_fin": "2024-06-30",
    "is_active": true
  }
  ```
- **Response Exitosa (201 Created):**
  ```json
  {
    "semester_created_id": 1,
    "mensaje": "Semestre 1 registrado correctamente",
    "semester": {
      "id": 1,
      "student": 1,
      "numero": 1,
      "fecha_inicio": "2024-01-15",
      "fecha_fin": "2024-06-30",
      "is_active": true,
      "created_at": "2025-01-15T10:00:00Z",
      "updated_at": "2025-01-15T10:00:00Z"
    }
  }
  ```

### Endpoint: Listar Semestres de un Estudiante
- **URL:** `/api/v2/students/<id>/semesters/`
- **Método:** `GET`
- **Response Exitosa (200 OK):**
  ```json
  [
    {
      "id": 1,
      "student": 1,
      "numero": 1,
      "fecha_inicio": "2024-01-15",
      "fecha_fin": "2024-06-30",
      "is_active": true,
      "created_at": "2025-01-15T10:00:00Z",
      "updated_at": "2025-01-15T10:00:00Z"
    }
  ]
  ```

## 5. Implementación Técnica
- **Backend:**
  - `backend/apps/students/models.py`: Modelo `Semester` con `MinValueValidator(1)`, `MaxValueValidator(6)`, `UniqueConstraint(fields=['student', 'numero'])` y validación `clean()` de coherencia de fechas.
  - `backend/apps/students/serializers.py`: `SemesterSerializer` con validaciones de fechas y límites numéricos.
  - `backend/apps/students/views.py`: Acción `@action(detail=True, methods=['get', 'post'], url_path='semesters')` en `StudentViewSet` y `SemesterViewSet`.
  - `backend/apps/students/tests.py`: Pruebas exhaustivas para semestres válidos (1 a 6), validación de errores (>6, <1, fechas invertidas, duplicidad).
- **Frontend:**
  - `frontend/src/app/core/models/student.model.ts`: Interfaz `Semester`.
  - `frontend/src/app/core/services/student.service.ts`: Métodos `getStudentSemesters` y `createSemester`.
